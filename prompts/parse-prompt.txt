Summarize data from the posts.message fields for these news editions.
Do not create a script to do this, but manually read through and categorize/save events from the message contents.

Goal: Extract data into each edition's folder as json files.
Example: Folder "1" would extract from "1/posts.json" and save the results to "/events.json"

The contents of events.json should be json and have 1 root properties: events
All events should include the thread link associated to them - typically ending in tid=
All users should include the UID along with the username if provided

Events should have the following properties:
- category: category of the event (same values as topic used to use; see below)
- title: Short title summary of the event (if there is no title, derive one from the description)
- description: Additional detail about the event - details go here
- url: url of the related thread (use "" when there is no link)
- users: array of uid & username object
- date: the date of the first post in posts.json - example: 1289072975

Do not create events that only summarize off-site world news, general technology industry news, or general gaming industry news (for example long third-post columns with no Hack Forums thread to attach). HF threads that appear in the edition’s linked notable-thread lists are still in scope for `threads` when they meet the notable-thread rule.

Individual events need to be labeled by category: 
- site: Headlines/Site News - events related to the site (which is HackForums) or the owner (Omniscient)
- users: User News / Bans / vacation bans / closures/ receiving Awards/ RepFucks (RKOs) - should always be associated to a user. Each user event, even if multiple users had the same type of event, should have their own event entry.
- groups: Group News - anything relating to groups, like being sold, created, or recruitment related threads
- threads: Notable Threads - must be under a notable threads section, otherwise dont include them
- news: The list of users that contributed to that edition (each edition should have 1 event for this category)
- interviews: an interview entry for each member interviewed in an HF News edition - only the user BEING interviewed should be included in users. The interviewer should not be included as long as they are referenced in the news category of that edition.
