[b][size=medium]Purpose[/size][/b]

This project preserves the events covered in each Hack Forums News edition — site changes, member awards, group activity, notable threads, and the writers behind each edition — as machine-readable JSON. By keeping a curated mirror offsite, the archive ensures the history survives thread deletions, account closures, [i]nuclear explosions[/i], and any other future changes to the site.

[hr]

[b]Features:[/b]
[list]
[*][b]560+ editions[/b] covered, going all the way back to Edition 1 (2010).
[*][b]7,100+ individual events[/b] — site announcements, awards, group changes, notable threads, contests, contributors, and more.
[*]An event [b]web viewer[/b] with full-text search, user filter (by username or UID), category filter, date range, and sortable order.
[*]Fully [b]open source[/b] — everything is in a public GitHub repo, including the raw post/blog data the events are curated from.
[/list]

[b][size=medium]FAQ[/size][/b]

[spoiler]
[b]What is the purpose of this archive project?[/b]
To preserve the historical record of Hack Forums News events in a place that does not depend on Hack Forums itself or the HF Wiki. Both of those can change, lose content, or disappear; this repository keeps a portable, structured copy so the history remains accessible regardless of what happens to the primary site.

[b]I found an error or missing event, can you fix it?[/b]
The fastest path is to fix it yourself: clone the repository, edit the relevant [b]editions/<N>/events.json[/b] (or add a new one), and open a pull request. Corrections, newly discovered events, and other improvements are all welcome. If GitHub isn't your thing, you can also just drop a reply in this thread and I'll get to it on the next pass.

[b]Where does the data come from?[/b]
Most editions are pulled from their Hack Forums thread via the HF API, which writes the raw posts into [b]editions/<N>/posts.json[/b]. Editions 442–508 were sourced from member blog dumps ([b]blogs.json[/b]) instead. From there, each edition's [b]events.json[/b] is curated by hand following the conventions in the parse prompt.

[b]Why are some editions missing?[/b]
The source content is gone. Some news threads were deleted, junked, or migrated away before the archive existed; some blogs were never captured. The 32 affected edition numbers are listed above. If you have a copy of any of them, please open a pull request adding the source data.

[b]Is there a viewer / web UI?[/b]
Yes — the web viewer at [url=https://xadamxk.github.io/hf-news-archive/]xadamxk.github.io/hf-news-archive[/url] is a static React app for browsing every event in the archive. The source for the viewer lives in the [b]viewer/[/b] directory of the repo if you want to run it locally.

[b]Can I contribute? How?[/b]
Pull requests are welcome. Common contributions: filling in details on existing events, adding events that were missed, or adding entire editions (especially anything from the missing list). The viewer uses Bun; the post fetcher uses Node and needs a Hack Forums API token.

[b]What do "Journalist (Section)" and "Contributor" roles mean?[/b]
On the [b]Contributors to this edition.[/b] event, each contributor carries a [b]role[/b] string. [b]Journalist (Headlines)[/b], [b]Journalist (Awards / Tech)[/b], etc. means that member wrote the named section(s) of the edition. [b]Contributor[/b] means they appeared in the closing "thank you" credits without being attributed to a specific section.

[b]How often is the archive updated?[/b]
The archive is updated manually, so expect long gaps — sometimes months — between catch-up passes. New editions are added in batches when time allows rather than on a fixed schedule.

[b]License / data reuse terms?[/b]
Feel free to extract whatever you want from the events.json data for your own projects. If you do build something on top of the archive, please help keep it current by sending fixes and new editions back upstream so everyone benefits from the same history.
[/spoiler]
